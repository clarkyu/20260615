- **教学结构**：多班一次发布、各页班级/学期/状态筛选、院系/专业从字符串规范化为实体（#2–8）。

- **登录与品牌**：统一登录（学校下拉 + 学号/工号 + 密码）、改名「你好！作业」、切域名 + 强制规范域 308 跳转（#14–18）。
- **提交体验重设计**：提交类型（文本/音频/视频/手写拍照）+ 分类；学生录制流（3-2-1 倒计时、竖屏镜像、常驻「请闭眼背诵」）、老师逐个批改流、老师首页行动台 + 待批看板（#11–13, 19–22）。

<summary><b>② AI 教育内核 · 五段式重构（#23–32 · 06-15~16）</b> —— 产品差异化骨架</summary>

把「世界级 AI 教育产品」拆成五段地基，逐段落地：

1. **评分领域层 + 置信度分流**（#23）：编排抽到 `domain/grading`，`decideReview` 纯策略——高置信免复核、未知置信度默认复核（fail-safe）。
2. **学练闭环**（#24）：学生正式交前「练一练」（朗读→AI 即时点评→反复练），**无限次、不计正式次数**。
3. **AI 先批、只看例外**（#25）：提交即后台自动评分（Worker `waitUntil`，学生不等）、高置信自动通过、未配 key 优雅退回全人工不阻塞学生。
4. **学情分析**（#26）：零新表实时聚合——提交率/均分/**风险识别**（提交率<50% 或均分<60）/最薄弱句。
5. **AI 备课出题**（#27）：给主题或**拍课本照片** → 起草整份作业回填表单。

- 紧接一轮**质量审查修 4 个 CRITICAL**（#28）：媒体管线被 CSP/Permissions-Policy 掐死、练习接口 IDOR、置信度从未接真实模型（导致「高置信自动通过」生产从未触发）、裸 `JSON.parse(violations)` 致整页 500。
- 老师上手（加同事老师/手动建班/三步引导）、**平时成绩（练一练）vs 测试成绩（提交）分轨**（#29–32）。

<summary><b>③ 题库系统 · 内容资产（#33–41 · 86–123）</b> —— 跟读内容从空到 2000 句</summary>

- **三段式跟读**：每句 = 中心句 + 解释句 + 情境例句，各中英对照 + 整套跟读视频（#33–34）。
- **跟读闭环**：从题库一键发布 → 学生竖屏跟读 → **逐句录音逐句提交** → **逐句 AI 评分**（准确度·0.7 + 完整度·0.3，高分自动通过）（#35, 37, 40）。
- **课程脊柱**：`taxonomy`（CEFR / 技能树 / 领域 / L1 叠加）+ 句集分级元数据 + 按级别/技能/领域筛选（#86–89, 93）。
- **真·全局共享题库**（#90）：`ChunkSet.schoolId` 可空、整表重建迁移 0022（`PRAGMA defer_foreign_keys` 保子表外键）——具体 `schoolId` 永不匹配 `NULL` 行 → **全局官方集对普通老师天然只读**，无需额外判断。
- **批量内容**：官方样题包 + **English Flow 2000 整本接入**（40 套×50，仅服务端不进客户端包）+ 通用题包界面导入（粘贴拆套、不再每包改代码）+ **有界可恢复导入**（每次 ~600 chunk + 客户端续跑，避免 Worker 时限腰斩）（#88, 94–96）。
- **题库 UI 重做**：系列分组/可折叠/搜索/手机竖屏优先、老师端去冗余、收藏星标置顶、发布前内嵌编辑（#103–105, 158, 165, 172）。

<summary><b>⑤ 安全 · 正确性 · 测试纪律（#62–72 · 130–131 · 192–193 · 200 · 208 · 211–212）</b> —— 两次数据级事故 + 回归网</summary>

- **限流改 D1 共享存储**（#62）：原 per-isolate 内存计数 → 有效上限 = 设定值×isolate 数（暴力破解防护被绕开）；改一条原子 `INSERT…ON CONFLICT…RETURNING` 跨 isolate 共享。
- **8 连代码评审修复**（#65–72）：补 `FAILED` 计 attempt（防白得一次提交）、新一轮草稿盖住已评分（成绩漏分）、录像组件生命周期/内存泄漏、批改状态机走仓储。
- **🔴 两次数据级事故**：
  - **#130** 编辑作业（哪怕一字没改）→ `phase.deleteMany` 整删重建 + `onDelete:Cascade` → **删光所有学生提交/分数/练习**。修：按 phase id **就地对账**（保留→update 不换 id、新增→create、仅主动删的→delete）。
  - **#192** 校内 **IDOR**：列表早按角色 scope，但所有「按 id」明细/编辑/删除/评分只按 `schoolId` scope → 同校老师枚举 id 触达他人作业/课头/提交乃至学生视频；最直接是 `applyBatchOverride` 无老师归属校验。修：repo 层每处「按 id」staff 读写统一按角色 scope（TEACHER 限本人 offering）。
- **并发 fencing**（#131）：批改终态写入加 `status:PROCESSING` 守卫——慢任务被回收又被另一 isolate 重跑时不互相覆盖、不覆盖老师改分。
- **提权守卫**（#200）：`setStaffRoleInSchool` 只命中「同校 + 当前已是 TEACHER/SCHOOL_ADMIN」（学生提不成员工、超管改不动、不跨校）。
- **测试演进**：邀请 token 单次性 + 三 domain（#176，+24）、评分编排/逐句/越权写入（#193）、班级删除孤儿清理（#208）；**真 SQLite 集成测试**（#211–212）——37 条迁移重放到真引擎 + 真 PrismaClient，用真数据证明 IDOR 边界、真级联删除、`acceptAiForAssignment` 的 raw SQL、名单导入端到端。

<summary><b>⑦ 多环节作业（#124–137）</b> —— 作业 = 有序环节列表</summary>

- **模型升级**：把作业从「扁平单一要求 + 单时间窗」升级为「有序环节列表」，每环节各自内容来源 / 提交要求 / 时间窗 / 次数 / 是否计分（#124–125）。
- **三段交付 + 风险控制**：老作业自动转单环节（**纯增量**迁移 0027）、单环节逐字不变、新功能影响面锁在「全新多环节作业」（#124, 126–127）。
- **管线按环节**：Submission 唯一键加 `phaseId`（仅替换索引、零数据风险）；提交/批改/练习全部按环节；学生**分段呈现**（单环节直接进流程、多环节渲染环节清单）、老师批改每(学生,环节)一行（#126–127）。
- **统计全线对齐**：学情/成绩册/导出/薄弱句统一按环节汇总（计分环节均分、薄弱句按 phase 不混淆）、导出按环节拆列（#132–134, 177）。
- **配置全环节级**：类型 / 正式测试（强防作弊）/ 自由练习（不限次数·不进待批）均为环节级；**作业模板**（发布存为模板、本人/同校复用）（#136–137, 147, 160）。

</details>

**可改善空间（最值得投入，按回报排序）：**
1. **测试深度** —— 集成测试已补（#211–212）；仍缺**浏览器 E2E**（登录→提交→批改主流程）。两次数据级事故都是事后补测。

3. **运行时可观测性** —— 有 `wrangler tail`，但缺错误聚合（Sentry 类）与真实用户监控。
4. **CI 门禁** —— 只有 lint+tsc+test+build，无 SAST / 依赖漏洞扫描 / bundle 预算 / axe a11y。
5. **AI 层校准** —— 模型 id 写死会过期；置信度阈值（0.85）与逐句权重（0.7·0.3）是经验值、缺真实数据闭环。
6. **时区** —— 反复出 bug（#73/74/75/161/171）后已统一，建议沉淀为「一处时区工具 + 测试」长期守护。

**刻意取舍（非缺陷，均已记 tradeoff）：** 原生 Cloudflare Queues/DO 不做（可验证性优先）、定时任务走 Actions cron（分钟级漂移）、取消邮箱验证（易用优先）、防作弊仅前端提示。
