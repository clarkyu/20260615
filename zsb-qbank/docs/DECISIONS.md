# DECISIONS

记录 SPEC 未覆盖之处的实施决策(SPEC §0:选最简单可行方案并记录,不停下等确认)。

## D1 仓库落位(2026-08-26)
实施环境可推送的仓库仅 `clarkyu/20260615`,故 zsb-qbank 以**子目录**形式进入该仓库
(独立 package.json/lockfile/CI,与宿主互不引用;宿主 tsconfig 已排除本目录)。
未来需要独立仓库时用 `git subtree split` 拆出,历史可保留。

## D2 开发登录先行,Casdoor 后置(2026-08-26)
M0 验收只需要本地登录。已实现 `AUTH_DEV_LOGIN=true` 下的 `POST /api/auth/dev-login`
(iron-session HttpOnly Cookie,会话结构 `{ sub, name, role }` 与未来 Casdoor 对齐);
Casdoor OIDC(授权码 + PKCE)按 SPEC 计划在教师端里程碑前接入,届时仅替换登录入口,
会话与鉴权代码不变。

## D3 PWA 先 manifest,Serwist 后置(2026-08-26)
M0 验收清单要求的是 PWA manifest(已实现 `app/manifest.ts` + 图标)。Serwist 的
Service Worker(应用壳预缓存/试卷 JSON 运行时缓存)对离线作答真正有价值的时点是 M2
(本地保存 + 同步队列)——届时一并接入,避免 M0 就引入 SW 调试面。

## D4 本地验证用系统 PostgreSQL 16(2026-08-26)
实施沙箱无 docker daemon,但系统装有 PostgreSQL 16。M1 的迁移/种子/幂等验证在本地
真 PG16(initdb 临时集群,端口 55432)上执行,与 SPEC 要求的目标数据库同版本;
docker-compose.yml 照常提供给有 docker 的环境。CI 用 postgres:16 服务容器。

## D5 Zustand/Dexie 等前端依赖按需引入(2026-08-26)
M0 只安装当下会被 import 的依赖;Zustand + Dexie(离线作答)在 M2、Serwist 在 M2、
openai/mammoth/turndown 在 M4/M5 引入,避免脚手架期的幽灵依赖。

## D6 seed 断言仅对样本卷生效(2026-08-26)
`pnpm seed` 的 1-6-8-43-100 断言只在导入 `hubei-zsb-english-2025` 时执行,
其它试卷走同一导入路径但不套用该卷的常量。

## D7 M2 首页练习入口先列全部试卷(2026-08-27)
种子卷状态为 draft(主观题答案待教师核定),发布流转(draft→published)在 M5 教师端
落地。M2 首页对已登录用户列出全部试卷以打通练习链路;M5 上线后收紧为学生仅见
published、教师可见全部。`POST /api/attempts` 同步收紧。

## D8 M2 端到端验证用本地 dev server + 移动视口浏览器冒烟(2026-08-27)
正式 Playwright e2e 入 CI 仍待 M3(需要可复位的测试数据库);M2 以本地 dev server +
390×844 视口真浏览器手工冒烟覆盖:登录→开卷→填空→对答案→反馈卡→答题卡跳转→
刷新恢复,并在 PROGRESS 写明真机(微信)验收步骤。

## D9 自由模考可重复,任务考试的不可重做延后到任务链路(2026-08-27)
SPEC §6「考试默认不可重做」针对教师发布的任务考试;学生自发的模考(paperId + mode
=exam,无 assignmentId)不受限——已交的不挡新开,未交的续答同一 attempt(倒计时
不重置,即断线续答)。assignment 考试的不可重做与教师授权二次作答在 M5/M6 任务链路强制。

## D10 逾期自动交卷 = instrumentation 定时清扫 + 请求惰性兜底(2026-08-27)
§9.5 的「工作线程」在 Next.js standalone 部署下用 src/instrumentation.ts 实现:
服务启动后每 60 秒 sweepOverdueExams(截止 + 60 秒宽限已过的 in_progress 考试逐个
submitAttempt(auto));GET attempt / result 命中逾期时也惰性交卷,双保险。M4 引入
ai_jobs 工作线程后可并入同一循环。

## D11 e2e 入 CI:chromium 引擎跑双移动视口,串行执行(2026-08-27)
CI 只安装 chromium:iPhone 13 描述符默认 WebKit,两个 project 显式覆盖
browserName='chromium'(视口/UA/触摸仿真保留,引擎差异靠微信真机验收覆盖)。
workers=1 串行:模考流程同一开发账号会续答同一 attempt,并行会互抢考试。
e2e 步骤对 next start 的真服务执行,库就是同 job 已种子的 postgres:16 容器。

## D12 AI 调用不引 SDK,fetch 直连 OpenAI 兼容接口(2026-09-13)
M4 的评分/解析只需 chat/completions 一个端点:温度 0、response_format=json_object、30 秒超时、
用 AbortController 中止。直接 fetch 比引 openai 包少一层依赖与版本耦合,也便于在测试里注入
假调用器(AiCaller)对真库跑集成用例而不打真接口。错误按 kind 分类(timeout/network/http/
bad_response/not_configured):超时、网络、429/5xx 视为瞬时可重试;其余不重试直接分流待评。

## D13 成本日志记在 ai_jobs.result.usage + 控制台一行(2026-09-13)
不另建 ai_usage 表:每条任务的 promptTokens/completionTokens/latencyMs/model 存进
ai_jobs.result,同时 console.log 一行「[ai] grade job=… item=题号 tokens=p+c ms=…」——只记题号
与用量,不记学生内容(§9.5 个人信息最小化)。单价随模型而异,汇总换算在 M5 教师端做。

## D14 ai_jobs 工作线程并入 instrumentation,与逾期清扫同进程(2026-09-13)
SPEC §9.1「应用内轮询工作线程(间隔 2 秒,单进程)」:register() 里每 2 秒 processAiJobs
(每轮最多 5 条,同进程 busy 标志防重入),领取用 FOR UPDATE SKIP LOCKED,多实例也安全;
失败后按 attempts×5 秒退避重试,最多 3 次。AI 未配置时线程照常跑,把任务立即分流为
「待老师评」,学生端不会无限等待。逾期清扫(D10)保留 60 秒节拍。

## D15 提示词以 prompts/*.md 存放,standalone 产物显式带上(2026-09-13)
按 §5.3「提示词以文件形式存放,教师可改不动代码」:系统提示词 5 份在 prompts/,运行时
fs 读取并缓存;PROMPT_VERSION 参与缓存哈希,改提示词后旧缓存自然失效(需手动升版本)。
next.config 用 outputFileTracingIncludes 把 prompts/** 带进 standalone 产物;M7 的 Dockerfile
不必再单独 COPY。

## D16 练习模式 AI 反馈用轮询而非推送(2026-09-13)
§7.5 规定每 3 秒、最长 90 秒轮询:新增 GET /api/attempts/:id/feedback?itemIds= 只回已落库的
判分结果(考试模式 403);超时后反馈卡显示「稍后在成绩页查看」。不引 WebSocket/SSE,
微信内置浏览器与弱网下更稳。

## D17 送评答案快照进任务,写回前核对,悬挂任务超时回收(2026-09-13,评审后)
练习模式作答可随时改,入队与执行之间有窗口:任务 payload 保存入队时的答案快照与哈希,
工作线程只评快照,缓存按快照哈希写;写回 responses 前核对当前答案仍等于快照且非教师终评,
否则作废(job.result.applied=false,记 superseded),由下一次「对答案」重新入队。running
超过 5 分钟(> AI 超时)按进程崩溃遗留回收重跑;未预期异常把任务放回 queued 而非留在 running。

## D18 限速与防注入放在应用层,不引入网关(2026-09-13,评审后)
§9.5 的按用户限速用进程内滑动窗口(check 60 次/分钟、explain 30 次/分钟),单进程部署足够,
多实例各自计数即可。提示词注入防线两道:学生答案用 <student_answer> 标签包裹并在系统提示词
声明标签内指令无效;服务端启发式(对阅卷者的指令、分数/置信度赋值、JSON 片段)命中即强制
教师复核且结果不入缓存——宁可多送复核,不让注入拿满分。

## D19 汉译英兜底二值化;作文字数用封顶而非减法(2026-09-13,评审后)
§5.2 规定兜底只判「是否可接受」:提示词只允许满分或 0,服务端再 foldBinary 折成二值,去掉
partial。作文 minWords 不足:提示词让模型把字数维度记 0,服务端用「总分 ≤ 满分 − 字数维度」
封顶——模型已扣的不再扣、没扣的强制扣,不会双重扣分。

## D20 批改队列的可见范围 = 本教师班级任务 + 无任务的自由练习(2026-09-14)
SPEC §8 只说「列出所有 needs_review」。多教师预留下按班级归属隔离:教师只见自己班级任务下的作答;
学生自发练习 / 模考(无 assignmentId、无班级)没有归属,对所有教师可见可批——否则这些待评题永远没人管。
概览「待复核」计数同口径。

## D21 教师终评保留 AI 分,确认即沿用(2026-09-14)
§5.3「AI 评分与教师评分分别保存在 grade_detail」:改分写 grade_detail.teacher{score,by,at,confirmed},
grade_detail.ai 不动;「确认 AI 分」= 以当前分数落 teacher 终评(confirmed=true)。gradeSource=teacher 后
AI 线程不再覆盖(M4 已保证)。客观题也允许教师改分(处理题目数据异常),verdict 按满分与否重写。

## D22 学情统计以「已交卷人数」为分母,常见错答按任务内作答统计(2026-09-14)
未开始 / 作答中不计;未作答按 0 分计入平均;待评主观题不进平均分分母。§5.4 的 wrong_answers 表是全库
累计(学生端练习反馈用),教师学情页的「每题前五常见错答」按本任务已交作答规范化后统计,更贴合班级。
「每题中位用时」无埋点数据,首期不算、页面明示(M6 作答计时后补)。

## D23 CSV:UTF-8 BOM + CRLF + 公式注入防护(2026-09-14)
验收要求「Excel 直接打开且中文不乱码」:BOM 让 Excel 按 UTF-8 解码;CRLF 兼容 Windows;以 = + - @ 开头的
非数值字段前置单引号,防止学生答案被当公式执行;文件名用 RFC 5987 filename* 带中文。

## D24 docx 导入:多空格保真 + 规则不猜 + 文末答案喂 AI + 整卷重建保护(2026-09-14)
HTML/Markdown 会折叠连续空白,而试卷空位正是「多空格」:转 Markdown 前把 ≥2 个空格换成不间断空格,
校对页显示无异、规则引擎可识别。规则引擎拿不准处一律打 flag 进 issues(校对页标红),不静默猜测(附录 B);
折叠成单空格的数字只在完全找不到空位时按序号兜底并标红。文档末尾若附「参考答案」(大题序号从头再来或
出现该标题),整段截出交给 AI 按题号采用,准确度远高于让模型自己做题。ai_jobs 复用 kind=parse,AI 未配置
也产出可校对草稿。整卷写入走 upsertPaper(删旧建新,小题 id 会变),已有作答记录的试卷拒绝重建(409),
改用小题编辑;新卷请换 id 另存。

## D25 练习任务也要「完成」;名单与学情取代表性作答(2026-09-14,评审后)
练习模式的 attempt 原本永远 in_progress(练习只有「对答案」),老师端名单 / 学情 / 发布对练习任务永远是
0 已交。作答页练习模式在最后一组给「完成」按钮(走同一个 submit 接口,之后仍可再练一次);名单 / 学情按
「最近一次已交的作答」统计,一次都没交才显示作答中——交过卷再练一次丢在半路,成绩不会消失。学生卡片
仍指向正在作答的那份(续答优先)。

## D26 展示时区固定北京时间(2026-09-14,评审后)
容器多为 UTC,服务端组件按本地时区格式化会比老师看到的晚 8 小时,客户端组件又会与服务端 HTML 不一致
(水合警告)。师生都在国内:所有时间展示走 Intl.DateTimeFormat + Asia/Shanghai,服务端与客户端输出一致。
录入用的 datetime-local 由浏览器按本地时区转 ISO,不受影响。

## D27 小题改动作废 AI 缓存与常见错答;整卷重建的保护范围(2026-09-14,评审后)
教师改了参考答案 / 题干 / 分值,按旧答案键算的 ai_grade_cache 与 wrong_answers 一并删除(后来的学生
不会命中旧缓存拿到旧判分),分值变了试卷满分同步重算;已落库的作答不回溯(老师在批改队列改分)。
整卷重建(PUT papers/:id)在「有作答记录」之外也拒绝「被勾选小题的任务引用」的试卷——重建会换小题
id,任务的 itemIds 会悬空。导入向导建议的 id 若已存在自动加 -import 后缀,不会悄悄覆盖种子卷。

## D28 开始作答加事务级咨询锁;教师写接口限速(2026-09-14,评审后)
「先查再插」在双击 / 双设备下会建出两份 in_progress:判定与插入放同一事务,按 (任务, 学生) 取
pg_advisory_xact_lock,第二个请求等锁后走续答;不加唯一索引(免迁移,且练习允许多份历史作答)。
§9.5 的写接口限速在 requireTeacherApi(req) 里对非 GET 统一 120/分钟。路径里的 id 先验 uuid 形状,
畸形 id 返回 404 而不是让 Postgres 抛 22P02 变 500。

## D29 训练作答只存服务端,每人每天一份训练 attempt;AI 兜底不回溯复习卡(2026-09-14)
§6 训练模式「保存:服务端」:不走 IndexedDB 同步队列。每人每天(北京时间)一份 mode=training 的
attempt,responses 按 (attempt, item) 唯一,重做同题覆盖最新一次;作答时把「这次是复习还是新题」记进
grade_detail.training,每日任务进度据此算。汉译英未命中词表时照 §5.2 交 AI 兜底并返回 pending,但复习卡
与脚手架按即时客观判定更新(未命中先按错处理),AI 判可接受只改本次分数,不回溯改卡——训练要的是即时
节奏,偶尔多复习一次无害。

## D30 复习卡只为答错过的题建立;掌握 = 走完阶梯再答对(2026-09-14)
「错题本」= review_cards:答对不建卡(题库几百题全建卡会把「今日复习」灌满),答错建卡次日到期;
连对按 1/3/7/14/30 天阶梯,超出阶梯封顶 30 天,streak > 5 视为掌握。答错 streak 归零、lapses+1、
回到 1 天(§10「错题重置」)。ease 字段保留 2.5 未用(为以后按难度调节留位)。

## D31 变式题从 1001 号起以草稿入原题题组;干扰项存 content.distractors(2026-09-14)
items 有 (paper_id, number) 唯一索引,变式题号接在 max(1000, 当前最大题号) 之后,与真题题号一眼可分;
挂在原题的题组 / 大题下以复用材料与说明。status=draft 的题不进 assemblePaper(练习 / 考试 / 学生端)、
不进学情、不被训练抽到,教师在试卷页「待审核变式」通过或删除(只能删 origin=ai 的草稿)。一级脚手架的
干扰项按 §6 由 AI 生成、教师采纳后写入 content.distractors(schema 可选字段);发往学生端时剥掉,
只以「选项」形式出现在一级脚手架里。

## D32 standalone 产物钉住 outputFileTracingRoot(2026-09-14)
本仓库是「宿主仓库 + zsb-qbank 子目录」,外层还有一份 lockfile,Next 会把工作区根推断到外层,
`.next/standalone` 里就多嵌一层 `zsb-qbank/`(本地构建如此),而 Docker 构建上下文只有子目录时又不嵌——
同一份 Dockerfile 的 COPY 路径在两处行为不同。`next.config.ts` 显式 `outputFileTracingRoot: __dirname`
把布局钉死:`server.js` 永远在 `.next/standalone/server.js`。

## D33 迁移与种子跑在 tools 容器(2026-09-14)
运行镜像是精简的 standalone 产物(只含被 trace 到的运行时依赖),没有 tsx,跑不了 `scripts/*.ts`。
compose 增加 `tools` 服务(profile=tools,不随 up 启动),用构建层镜像跑
`docker compose run --rm tools pnpm db:migrate / pnpm seed`。不在应用启动时自动迁移:
自动迁移在多副本或回滚场景下难以预期,显式一条命令更好复盘。

## D34 Origin 校验放在 middleware,缺 Origin 放行(2026-09-14)
§9.5 要求写接口校验 Origin。放在 `src/middleware.ts` 一处覆盖 /api 全部写接口,免得每个路由各写一遍
(edge 运行时只读请求头,不碰数据库)。判定用纯函数 `lib/http/origin.ts`:同源(按 `X-Forwarded-Host` /
`X-Forwarded-Proto` 还原真实站点)或 `APP_ORIGIN` 白名单放行;**没有 Origin 头的请求放行**——浏览器发
跨站非简单请求必带 Origin,没有就不是浏览器(curl、健康检查、服务端到服务端),不构成 CSRF,
拦了反而挡住运维脚本与 e2e。

## D35 学生只见已发布试卷;种子卷随 M7 发布(2026-09-14)
D7 的收紧在 M7 落地:学生端自由练习只列 `published`,自由开卷也只放行 `published`(任务作答由教师
发布任务把关,不受此限);教师试卷页给发布 / 撤回 / 归档开关。种子卷(2025 真题)状态改为 published
——它的客观题答案有「参考答案得满分」用例覆盖、主观题参考答案与要点在 M4–M6 一路用于 AI 评分与
教师复核,再留在草稿里只会让部署后的练习入口是空的;新导入的卷仍默认草稿,必须教师确认后发布。

## D36 Casdoor 走授权码 + PKCE,id_token 不验签但逐条校验声明(2026-09-14)
SPEC §9.1 要的就是授权码 + PKCE。id_token 是服务端拿 client_secret 直接从 token 端点(TLS)换来的,
不经浏览器,OIDC Core 3.1.3.7 允许在这种情形下跳过签名校验——省掉拉 JWKS 与缓存轮换的一整套代码;
iss / aud / exp / iat / nonce 仍逐条校验,state 一次性且 10 分钟过期。将来若改成前端直连或引入
implicit / hybrid 流,必须补验签。

## D37 角色来自 Casdoor 的组,不在本系统维护(2026-09-14)
本系统不做用户管理界面:谁是老师由 Casdoor 的组 / 角色决定(`CASDOOR_TEACHER_GROUPS` /
`CASDOOR_ADMIN_GROUPS`,默认 teacher,教师 / admin,管理员)。每次登录按当前声明重算角色并覆盖会话,
组变了下次登录即生效。会话只存 sub / 姓名 / 角色,邮箱手机号一概不取(§9.5)。

## D38 未配置 Casdoor 时回落开发登录,不是二者并存(2026-09-14)
三项配置齐全才显示「统一身份登录」;`AUTH_DEV_LOGIN=true` 才显示开发登录。生产上应当只开前者
(RUNBOOK 已写明)。这样本地开发不必架 Casdoor,线上也不会留一个一键变教师的后门。

## D39 Service Worker 的缓存范围按「有没有个人信息」划,不按性能划(2026-09-15)
SPEC §9.2 说「预缓存应用壳,运行时缓存试卷 JSON」。落地时按一条更硬的线来划:
**手机可能是共用的、使用者是未成年人,所以缓存里能留下什么是安全问题**。
只缓存四类:构建产物(内容哈希)、断网兜底页 `/offline`、作答页 / 成绩页的壳
(这两张是客户端组件,HTML 里没有学生数据)、以及进行中的那一份作答 `/api/attempts/:id`
(唯一带个人数据的一份,缓存它才谈得上「断网接着做」)。首页 / 训练页 / 教师端都是服务端渲染
带姓名与任务的,一律不缓存 —— 断网打开它们看到的是「现在连不上网」,这是有意的。
见到任何 `/api/auth/*`(登录、回调、登出)就清掉带个人数据的缓存,换个人用这台手机读不到上一个人的卷子。
`/api/time` 永不缓存(硬约束 6:计时以服务端为准)。判断逻辑放在 `lib/offline/cache-policy.ts`
做成纯函数 + 表驱动用例,和判分规则同一个思路:改错了要有测试挡着。

## D40 离线的「打得开」只验缓存内容,「拔网线」放真机(2026-09-15)
写 e2e 时发现 Chromium 的离线仿真对 Service Worker 转发的**导航**请求不稳定:同一个
`setOffline(true)` 下,页面里的 `fetch` 被正确拦截,有的整页导航却照样通到了服务器
(开着 navigationPreload 时尤其明显——因此顺手把它关了,那点首字节不值得让行为变得不可预测)。
所以自动化只断言两件确定的事:**缓存里只有允许的路径**、**登出会清掉个人缓存**;
「飞行模式下刷新作答页仍打得开」写进 RUNBOOK 的真机验收矩阵(§三 第 6 条)。
宁可测少一点也不要一个时好时坏的用例。

## D41 accepted 候选从 responses 里捞,拒绝的记进 wrong_answers(2026-09-15)
候选的来源有两处可选:ai_jobs 的执行结果,或 responses 表。选 responses:
**AI 判了满分(`grade_source='ai'` 且 score = 满分)的作答,就是 AI 认为可接受的答案**——
它是永久记录,不随任务表清理而消失,也天然带「几个人这么写过」的计数。
拒绝的候选记进 `wrong_answers`:老师说「这个不可接受」,那它本来就是个错答,
既用来把它挡在候选列表外,又让「常见错答」更准 —— 不必为此新开一张表、加一次迁移。
采纳会清掉该题的 AI 评分缓存(缓存是按旧答案键算的),但**不回溯改学生已得的分**,
与单题编辑同一口径(改分走批改队列,教师分是终评)。

## D42 题库筛选条件全走查询串(2026-09-15)
`/teacher/bank` 的试卷 / 年份 / 题型 / 知识点 / 状态 / 来源 / 题号 / 翻页全部是 URL 参数,
页面是 Server Component 直出,不做客户端状态。这样一个筛选结果可以直接把链接发给同事,
刷新和前进后退都不丢;代价是每次筛选一次往返,题库这个量级(百来道题)完全不值得为此上客户端表格。
答案键上限 50 条(`MAX_ACCEPTED`):判分要逐条比,也防手滑把几百条候选全采纳进去。

## D43 每题用时按「停留在这道题上的时间」算,埋点尽力而为(2026-09-15)
SPEC §8 要「每题中位用时」,但没定义什么叫「这道题的用时」。定为**停留时间**:
切到某道题(进入题组、点某个空)开始计,切走 / 页面切后台 / 交卷结束计;同一题多段相加。
不按「第一次敲键到最后一次敲键」——那样单词填空会算出接近 0,没有意义。
三条防脏数据的规则:单段超过 3 分钟按 3 分钟计(人把页面开着走开了)、单题累计封顶 30 分钟、
时钟倒退的段直接丢弃。客户端发的是**累计值**,服务端取较大者(`mergeTime`),
所以重试与乱序到达都不会让它倒退。
埋点是**尽力而为**:整条链路的 try/catch 都是静默失败 —— 作答先落 IndexedDB 是硬约束 7,
统计口径绝不能挡住作答。没埋到的作答在学情页显示「—」,不拿 0 充数(否则中位数被拉到 0、老师被误导);
页面上同时显示样本数,老师知道这个中位数是几个人算出来的。

## D44 未发布成绩时,只遮「答了的」主观题(2026-09-15)
SPEC §9.4 要求成绩未发布时主观题只显示待评。原实现把**所有**主观题都改成 `pending`,
包括学生根本没作答的 —— 空卷交上去,成绩页会说「还有 11 题在等 AI 或老师评分,评完后刷新
本页总分会更新」,学生会一直刷新等一个永远不会来的分数,「未作答」题数也少算了
(空库预演里 43 题的空卷显示成「32 题没作答 + 11 题在等」)。
改为只遮 `verdict !== 'empty'` 的主观题:没作答的本来就是 0 分,没有临时分需要遮。

## D45 导入的小题直接是 approved,不再走第二次逐题审核(2026-09-15)
`ruleDraftToPaper` 原本把导入的小题一律存成 `status='draft'`,但**学生端所有查询只认
`approved`**(组卷、判分、训练抽题、学情)。于是「导入 → 校对 → 保存 → 发布 → 布置任务」
之后,学生打开是一份 **0 题的空卷**,而试卷列表明明写着 43 题 —— 用真 2026 卷预演时实测到
「已答 0/0」。教师在校对页已经逐题确认过了(向导原话「拿不准的地方会标红,你逐题确认后保存」),
再要求他在试卷页点 43 次「通过」既多余、又埋了这个坑。
改为导入的小题存 `approved`;试卷本身仍是 `draft`,学生看不看得到由教师点「发布」把关(D7 不变)。
`draft` 留给 AI 变式题(SPEC §8:变式题审核通过才能被训练抽到),`origin` 已能区分两者。
已经导入过的旧数据用一条 SQL 修(RUNBOOK §三点五 附)。

## D46 批改队列的筛选项跟随当前 scope(2026-09-15)
批改页在超过 `QUEUE_LIMIT_DEFAULT`(500)条时提示「请用上面的任务 / 小题筛选缩小范围」,
但 `queueFacets` 原本写死只按 `needs_review` 统计筛选项。AI 工作正常时待复核为 0,
于是老师切到「抽查全部主观题」(恰恰是条数最多、真会被截断的那一档)看到的是**空筛选栏**:
页面让他筛,却没有东西可筛。40 人班的规模预演里实测到 524 条队列 + 0 个筛选项。
改为 `queueFacets(db, teacherId, scope)`,scope 与队列查询用同一套条件;默认仍是 `needs_review`,
老调用不受影响。`pendingReviewCount`(顶部「待复核」计数)仍只数待复核,不跟随 scope。

## D47 同步队列没清空就不许交卷(2026-09-16)
弱网预演实测到一次真丢分:保存作答的 `PUT /responses` 坏了、交卷的 `POST /submit` 却是通的
(网关抖动、请求体超限、代理超时都会造成这种「一半网络」),`flushNow()` 又把同步失败全吞了,
于是交卷照常成功 —— 服务端只有第 1 空,学生写的另外 3 空停在手机上,而交卷后保存接口对已交的
attempt 一律返回 409「已交卷,不能再保存」,这几空**永远补不回来**,按没答判 0 分。
顶栏当时明明写着「保存中」,弹窗却写「答案已存在手机上,不会丢」——正好说反。
改为 `flushNow()` 返回「作答是否全部送达」,交卷前必须为真;不为真就拦下来并告诉学生还差几题、
答案还在手机上、连上网点「重试」能补。**到点自动交卷是唯一例外**(`force`):那时服务端过了
60 秒宽限本就不再收保存,拦着只会把人困在一个走不掉的页面上。
练习模式的「对答案」同理:没送达就不判,否则判的是服务端的旧底稿,会把刚写过的题报成没答。

## D48 「只差用时埋点」不算没同步(2026-09-16)
承 D43(埋点尽力而为):`persistTime()` 补用时的时候会把行重新标脏,而 `flushNow()` 每次开头
都 `stop(timer)` → 必然产生这样一行。如果 D47 的拦截照单全收,**只差一条埋点也会挡住交卷**,
跟 D43「埋点出问题不能影响作答」直接打架。给本地行加 `timeOnly` 标记:作答已送达、这次只补用时的
标 1,`pendingCount()` 不数它。交卷少一条用时无所谓(服务端 `mergeTime` 取较大者),
少一题作答是事故。

## D49 预热离线壳要等 SW 接管,不能见 controller 为空就放弃(2026-09-16)
`warmShell()` 原本 `!navigator.serviceWorker.controller` 就直接 return。实测学生**第一次**打开
作答页时 mount 那一刻 controller 还是 null(SW 正在装,几秒后才 claim),于是第一次开的那份卷
永远没有离线壳,断网一刷新只能弹到 `/offline` —— 而第一次用恰恰最容易乱点乱刷新。
改为等 `controllerchange` / `ready` 之后再预热(没接管时发请求也是白发,根本不经过 SW)。
原有的 e2e 因为在进作答页**之前**就等了 controller,把这个洞遮住了;新用例先注销 SW 再刷新,
把「第一次用」的状态造出来。

## D50 计时类 e2e 允许直连数据库把截止时间调近(2026-09-16)
「到点自动交卷」这条线只能等真的到点才测得到,而自由模考的 deadline 是 `now + 试卷时长`
(120 分钟),CI 里没法等。`tests/e2e/exam-deadline.spec.ts` 因此用 `pg` 直接把这场考试的
`deadline_at` 挪到十几秒后。这是**前置条件**而不是绕过被测代码:老师给任务设一个近的截止时间时,
`examDeadline()`(`min(now + 时长, 截止)`)产出的就是同样的短 deadline,跑的仍是真实代码路径。
代价是这个 spec 多了一个 `DATABASE_URL` 依赖(没有就 skip,与已有的 `E2E_BASE_URL` 同款)。
另外这几条一旦失败会留下一份逾期的「作答中」,后面的用例按「未交的续答同一份」接过去会连环红,
所以加了 `afterEach` 清场——让失败停在它自己身上。

## D51 作答时间戳送出前校正到服务端时间轴(2026-09-16)
服务端合并作答的规则是「`clientUpdatedAt` 新者胜」,而这个时间戳原本直接取自**设备时钟**。
双设备预演实测到真丢分:学生在 A 机(时钟快 10 分钟)写了错答案,换到 B 机改对,
服务端保留的却是 A 那份错的 —— B 的屏幕上是对的,交上去是错的,谁都不知道。
这和硬约束 6 同源:设备时钟不可信。硬约束 6 早就为倒计时立过规矩(以服务端 `deadline_at` 为准、
客户端按 `serverNow − Date.now()` 的偏移只做显示),这里复用同一个偏移:`flush()` 送出前把
时间戳加上偏移落到服务端时间轴,`init()` 的本地/服务端合并也按同一口径比。

**为什么不干脆改用服务端接收时间**:那会破坏离线场景 —— 学生断网时写的答案(真实时刻较早)
联网后才补传,按接收时间会盖掉另一台在线设备后写的新答案。`clientUpdatedAt` 的存在就是为了
表达「这条是什么时候写的」,要修的是它的**时间轴**,不是把它换掉。

**为什么不在服务端钳制**(拒绝超过服务端当前时间的时间戳):只挡得住时钟**快**的一半,
时钟**慢**的设备后写的答案仍然会输给先写的。客户端按偏移校正两边都解决,且不改接口。
老客户端(缓存里的旧 JS)偏移为 0,退化成原行为,不会更糟。

## D52 409 不再当成「网络不好,待会儿重试」(2026-09-16)
保存作答拿到 409 有两种成因:这份卷在**另一台设备上交了**,或考试过了 60 秒宽限。
两种都意味着**重试一万次也没用**,而原来的 `flush()` 对所有失败一视同仁地指数退避,
于是学生盯着顶栏「保存中」一直等,还以为是自己网不好;#486 加的交卷拦截更会对他说
「还有 N 题没传到服务器……等网络好一点再点重试」——是假话。
改为:409 时停掉冲刷定时器、记下 `conflict`,顶栏给一条说真话的横幅(「这份卷已经交过了
(可能是在你的另一台手机上)」/「考试已经结束了」)并直达成绩页;点交卷也直接送去看成绩,
不再弹那句网络文案。
